# Problem 2: Handbook size and cost estimates

The vendor desk agent sends `data/shop_handbook.md` to the model on every call, so we estimate what the handbook alone costs.
Generated by `scripts/estimate_handbook.py`. Prices are from `data/prices.json` (`gpt-6-luna`).

## Token count

| Measure | Value |
|---|---|
| Characters | 28,903 |
| Words | 6,127 |
| **Tokens (tiktoken `o200k_base`)** | **10,058** |

That's about 2.87 characters per token, close to the usual ~4-character rule of thumb (7,226 tokens by that rule).
This counts the handbook text only. The API also counts message wrappers, the system prompt, the vendor document and the output, so real runs will show more input tokens.

## Prices (per 1M tokens)

| Rate | $ / 1M tokens |
|---|---|
| Input (uncached) | $0.1 |
| Cache write | $0.125 |
| Cached input (cache hit) | $0.01 |
| Output | $0.5 (not used here: the handbook is input only) |

## Cost of the handbook alone

Cost = tokens x rate / 1,000,000.

**One call, without caching:**
10,058 x $0.1 / 1,000,000 = **$0.0010058** (about 0.101 cents)

**One call, with caching:**
- First call writes the cache: 10,058 x $0.125 / 1,000,000 = **$0.0012572**
- Each later call reads the cache: 10,058 x $0.01 / 1,000,000 = **$0.0001006**

**1,000 calls, without caching:**
1,000 x $0.0010058 = **$1.0058**

**1,000 calls, with caching** (1 cache write + 999 cache hits):
$0.0012572 + 999 x $0.0001006 = $0.0012572 + $0.1004794 = **$0.1017**

## Summary

| Scenario | 1 call | 1,000 calls |
|---|---|---|
| No caching | $0.0010058 | $1.0058 |
| With caching | $0.0012572 (write) / $0.0001006 (hit) | $0.1017 |

Caching cuts the handbook cost of 1,000 calls by about **89.9%**. The first call costs 25% more than uncached because of the cache write, and every call after that costs one-tenth as much.

## Assumptions to check in Problem 4

- The handbook is a fixed prefix at the start of every prompt, so it can be cached.
- The cache stays warm between calls, so there is only one cache write in 1,000 calls. If the cache expires, each re-write adds another $0.0012572.
- The `o200k_base` count matches the model's own tokenizer. We'll compare it to the `usage` token counts from real runs.

**Checked in Problem 4:** see `output/cache_test.md`, "Real numbers vs. the Problem 2 estimates". The token count and cache-read price held up, but each document takes 2 model calls and about 21,500 input tokens, so the real bill per document is about twice this estimate.
